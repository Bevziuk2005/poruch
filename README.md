# Поруч

Офлайн-прототип вебзастосунку для швидкого пошуку місць допомоги та корисних інструкцій у кризовій ситуації.

## Що реалізовано

- перегляд локального списку точок допомоги;
- категорії: тепло, лікарні, генератори, укриття та аптеки;
- пошук за назвою, адресою або категорією;
- відкриття детальної інформації про точку;
- окрема сторінка з короткими офлайн-статтями;
- адаптивна верстка для телефона та комп’ютера;
- інтерфейс працює на локальних даних без бекенду.

## Технології

React, Vite, JavaScript, CSS, lucide-react.

## Запуск

```bash
npm install
npm run dev
```

Для перевірки production-збірки:

```bash
npm run build
npm run preview
```

## Використаний AI-агент

Для планування, реалізації, перевірки та code review використано OpenAI Codex. Робота виконувалась окремими промптами на кожному етапі, а не однією командою на створення всього застосунку.

## Етап 3. Реалізація програмного забезпечення

### Промпт

> Реалізуй фронтенд-прототип вебзастосунку «Поруч» на React + Vite без бекенду. Використай локальні дані. Додай сторінку карти допомоги зі списком точок, категоріями «Тепло», «Лікарня», «Генератор», «Укриття» та «Аптека», пошуком, фільтрами і модальним вікном з деталями. Додай окрему сторінку корисних статей. Зроби сучасний адаптивний дизайн для мобільного телефону й комп’ютера. Код розділи на зрозумілі частини, а всі основні дії користувача зроби робочими.

### Результат

Створено робочий клієнтський прототип: користувач може перемикатися між картою допомоги та корисними матеріалами, шукати точки, фільтрувати їх за типом і відкривати детальну інформацію. Дані зберігаються у файлі фронтенду, тому для демонстрації не потрібен сервер.

## Етап 4. Тестування та валідація

### Промпт

> Перевір реалізацію «Поруч» відповідно до вимог: навігація між сторінками, пошук, фільтрація точок, відкриття та закриття модального вікна, відображення статей, адаптивність. Запропонуй тестові сценарії для позитивних і граничних випадків. Окремо перевір випадок, коли пошук не дає результатів, і випадок, коли користувач обирає кожну категорію.

### Результат

Перевірено основні сценарії: пошук за назвою та адресою, вибір категорій, відсутність результатів, відкриття картки точки, закриття модального вікна та перехід до статей. Окремо перевірено вузький екран смартфона.

### Тестові сценарії

| ID | Сценарій | Очікуваний результат |
|---|---|---|
| TC-01 | Вибрати категорію «Лікарня» | Залишаються лише лікарні |
| TC-02 | Ввести «Солом’янська» | Відображається відповідна точка |
| TC-03 | Ввести випадковий текст | Показується повідомлення про відсутність результатів |
| TC-04 | Натиснути на картку точки | Відкривається модальне вікно з деталями |
| TC-05 | Перейти в «Корисне» | Відкривається список статей |
| TC-06 | Зменшити ширину вікна | Інтерфейс перебудовується для мобільного екрана |

### Виправлення після перевірки

Під час перевірки додано окремий стан для порожнього результату пошуку. Тепер замість порожнього місця користувач бачить повідомлення: «Нічого не знайдено. Спробуй інший запит або категорію».

## Етап 5. Code Review за допомогою AI-агента

### Промпт

> Проведи code review проєкту «Поруч». Перевір читабельність React-коду, структуру компонентів, дублювання, обробку порожніх результатів, доступність кнопок, адаптивність, безпеку та потенційні проблеми продуктивності. ### Результат

Під час перевірки підтверджено, що основний функціонал працює на локальних даних і не залежить від API. Для покращення читабельності використано окремі масиви даних, компонент іконки точки та обробник навігації. Залишене обмеження прототипу: дані не синхронізуються між користувачами, оскільки бекенд не входить у цю версію.
